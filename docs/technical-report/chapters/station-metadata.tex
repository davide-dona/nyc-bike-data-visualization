\section{Station Metadata Dataset (GBFS)}
To enhance the station data provided by Citi Bike, we incorporate the real-time feed published in \href{https://gbfs.org/}{General Bikeshare Feed Specification} (GBFS) format and documented on the \href{https://citibikenyc.com/system-data}{Citi Bike System Data} page.

\subsection{Dataset Structure}
Unlike historical trip records, station metadata is served via a public JSON API adhering to MobilityData's \href{https://gbfs.org/}{GBFS} standard.
From this service, we query two key Citi Bike endpoints:
\begin{itemize}
    \item \texttt{station\_information.json}: Static properties like location and capacity, whose content changes only when the network itself changes.
    \item \texttt{station\_status.json}: Live availability and operational state.
\end{itemize}

\subsubsection{Original Structure}
The two endpoints share the \texttt{station\_id} field, on which they are merged to produce a unified station record comprising:

\begin{itemize}
    \item \textbf{From \texttt{station\_information}:}
    \begin{itemize}
        \item \textbf{Station ID}: internal GBFS identifier, a UUID for most stations and a numeric string for the rest.
        \item \textbf{Short Name}: public station identifier used for joins with Citi Bike trip data.
        \item \textbf{Name}: station name.
        \item \textbf{Latitude} and \textbf{Longitude}: station coordinates.
        \item \textbf{Capacity}: total number of docks installed at the station.
    \end{itemize}

    \item \textbf{From \texttt{station\_status}:}
    \begin{itemize}
        \item \textbf{Bikes available}: currently rentable bikes.
        \item \textbf{Vehicle types available}: per-type counts of the bikes currently at the station.
        \item \textbf{Docks available}: currently available docks.
        \item \textbf{Operational flags}: \texttt{is\_installed}, \texttt{is\_renting}, and \texttt{is\_returning}.
    \end{itemize}
\end{itemize}

Using the three operational flags (\texttt{is\_installed}, \texttt{is\_renting}, and \texttt{is\_returning}), we derive a boolean \texttt{active} indicator to filter out unavailable stations from live views.

\subsection{Data Quality}
The main quality issues concern unreported capacity, the self-consistency of the feed, and identifier consistency.
Ultimately, as demonstrated in the notebook, there are no missing values for stations in the feed.

\paragraph{Inactive Stations}
The feed includes stations being installed, repaired, or removed, all grouped under the \texttt{inactive} category.
They make up 101 out of 2,462 stations (4.1\%) and 2,043 docks (2.8\% of capacity).
Figure~\ref{fig:station_availability} shows why we remove them, since they report capacity but no live counts, and their bikes are out of service.
Keeping them would show false empty stations on the map and distort capacity stats without adding real bike availability.

\paragraph{Unreported Capacity}
The unreported capacity (Figure~\ref{fig:station_availability}) arises from using two different endpoints.
Station capacity is a static property provided by \texttt{station\_information} and updated periodically, whereas live bike and dock counts are delivered continuously by \texttt{station\_status}. 
Figure~\ref{fig:station_consistency} highlights this discrepancy, showing the per-station gap between declared capacity and the sum of live counters.
Filtering out the inactive stations described above eliminates the main source of variance without altering real availability.
For any remaining active stations that do not reconcile, dock states are read directly from live counters, treating capacity as a rough benchmark.

\paragraph{Identifier Consistency}
GBFS identifies stations in two ways: an internal \texttt{station\_id} (either a UUID or a numeric string) and a public \texttt{short\_name}.
Trip history files use only the latter: 93.8\% of station references in historical trips match a \texttt{short\_name}, whereas none match a \texttt{station\_id}.
Therefore, all joins between live metadata and trip history should rely on the \texttt{short\_name} field.

\paragraph{Live-Only Metadata}
Citi Bike provides station metadata only as a live feed, with no historical archives.
Consequently, removed stations retain their past trip records but lose all feed attributes, while newly added stations lack historical data, making them appear prematurely inactive.
This bias only affects feed-specific attributes like capacity and operational status, as each trip record independently contains its own station name and coordinates.
