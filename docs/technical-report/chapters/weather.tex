To enrich the analysis with meteorological data, we incorporate hourly NYC weather data retrieved from the \href{https://open-meteo.com/}{\underline{Open-Meteo archive API}}.

\subsection{Dataset Structure}
Weather data are queried via the Open-Meteo JSON API by specifying coordinates and a date range.
The API provides hourly data, updated with a few days' delay through an reanalysis model, offering a refined estimate of past conditions rather than keeping a live record of predicted weather.

\subsubsection{Original Structure}
The dataset includes several attributes. We focused on the following fields, as they are the one that most directly affect ridership:
\begin{itemize}
    \item \textbf{Timestamp}: Hourly observation time.
    \item \textbf{Temperature}: Air temperature in \si{\degreeCelsius}.
    \item \textbf{Precipitation}: Hourly precipitation in millimetres.
    \item \textbf{Weather Code}: WMO weather condition code.
    \item \textbf{Wind Speed}: Wind speed in km/h.
\end{itemize}

\subsection{Analysis and Insights}
Weather conditions serve as a key driver of daily bike usage.
Rather than examining weather in isolation, the following section focuses directly on its relationship with overall ridership patterns.

\paragraph{Ridership vs. Weather}
Figure~\ref{fig:rides_vs_weather} shows a clear inverse relationship between precipitation and usage: the month's peak precipitation directly coincides with its lowest ridership volume.
Meanwhile for the temperature, it's possible to see also a positive correlation with ridership, where the rides follows the temperature increase.
The accompanying notebook quantifies these daily relationships with Pearson correlation coefficients for daily ride counts versus daily mean temperature and total precipitation; the reported values are $r=+0.63$ and $r=-0.55$, respectively, for February 2025.
This confirms that weather tracking provides valuable context for interpreting demand fluctuations and supporting operational planning.

\subsection{Data Quality}
While the dataset is complete with no missing values across the timeframe, these inherent limitations are still important to note.

\paragraph{Spatial Coverage}
Weather data is retrieved for a single point centered on Central Park and applied across the entire system.
If it rains only in Central Park, but not elsewhere, the data will falsely show rain for the entire city, providing misleading information about the ridership patterns.
While this approach misses localized microclimates, introducing higher spatial granularity would add unnecessary modeling complexity for a city-scale analysis.

\paragraph{Timestamp inconsistencies}
Using local time to align with Citi Bike trip data introduces a one-hour error during Daylight Saving Time transitions (when clocks shift forward or backward by an hour).
This discrepancy misaligns weather records with ride timestamps, skewing the correlation between weather and trip activity.
