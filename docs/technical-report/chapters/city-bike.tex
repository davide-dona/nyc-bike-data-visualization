\section{City Bike Dataset}
For this project, our main dataset is the \href{https://www.citibikenyc.com/system-data}{Citi Bike system dataset}, a public repository tracking New York City bike trips since 2013.

\subsection{Dataset Structure}
Released monthly as open-data CSV files, these records log every completed ride, with high-volume months split across multiple files.
Each row represents a single trip, offering detailed attributes that characterize the journey.

\subsubsection{Original Structure}
The original dataset includes the following columns:
\begin{itemize}
    \item \textbf{Ride ID}: A unique identifier for each bike trip.
    \item \textbf{Rideable Type}: The type of bike used for the trip (``classic bike'' or ``electric bike'').
    \item \textbf{Started At}: A timestamp indicating when the trip started.
    \item \textbf{Ended At}: A timestamp indicating when the trip ended.
    \item \textbf{Start Info}: Information about the station and location where the trip started, structured as:
          \begin{itemize}
              \item \textbf{Station Name}: The name of the starting station.
              \item \textbf{Station ID}: The identifier of the starting station.
              \item \textbf{Latitude}: The latitude coordinate of the starting station.
              \item \textbf{Longitude}: The longitude coordinate of the starting station.
          \end{itemize}
    \item \textbf{End Info}: Information about the destination station, structured equally to Start Info.
    \item \textbf{User Type}: The type of user (``member'' or ``casual'').
\end{itemize}

\subsubsection{Extracted Features}
Additional per-trip features were derived to support the analysis:
\begin{itemize}
    \item \textbf{Trip Duration}: The duration of the trip in seconds, calculated as $\text{Ended At} - \text{Started At}$.
    \item \textbf{Trip Distance}: The distance between the start and end stations, computed using the Haversine formula and multiplied by a circuity factor of $1.3$ to better approximate real routes.
    \item \textbf{Day of the Week}: The weekday extracted from the end timestamp, which is used to partition the data since trips are published based on when they ended.
    \item \textbf{Hour of the Day}: The hour extracted from the end timestamp, for the same reason.
\end{itemize}

Beyond these per-trip features, two aggregated datasets are derived from the cleaned trip data to support station- and route-level analysis:
\begin{itemize}
    \item \textbf{Station Popularity}: for each station and time period, the number of trips starting and ending at that station, obtained by grouping trips by station.
    \item \textbf{Trips Flow}: for each pair of stations and time period, the number of trips travelling between them, obtained by grouping trips by station pair.
\end{itemize}

\subsection{Analysis and Insights}
To ensure transparency and reproducibility, the entire analysis is supported by \href{https://github.com/davide-dona/nyc-bike-data-visualization/blob/main/src/notebooks/analysis.ipynb}{\underline{Jupyter notebook}} within our repository.
The exploratory analysis is based on the February 2025 trip file (\href{https://s3.amazonaws.com/tripdata/202502-citibike-tripdata.zip}{202502-citibike-tripdata.zip}) and focuses on temporal, spatial, and behavioural patterns in bike usage.

\paragraph{Temporal Analysis}
Temporal analysis shows clear variations in demand depending on the hour of the day and the day of the week.
Trips are concentrated during commuting hours, while weekends show different usage patterns associated with leisure activities.

\subsection{Data Quality}
Various data quality issues were encountered during the analysis of the City Bike dataset.

\paragraph{Different Legacy Structure}
Around 2020, Citi Bike updated its trip-file schema.
Files from the 2013-2019 period use a legacy layout featuring different column names, dropped attributes, and distinct formatting (see the \href{https://github.com/davide-dona/nyc-bike-data-visualization/blob/main/src/notebooks/analysis.ipynb}{analysis notebook} for further details).
Despite these discrepancies, this historic data remains highly valuable.
To leverage it, the preprocessing pipeline implements specific schema adjustments, standardizing all monthly files into a single, compatible feature set.

\paragraph{Missing Station Values}
A small fraction of trips contain missing values, exclusively within the station-related columns.
The end-of-trip fields are the most affected: in a representative month, roughly $4{,}800$ trips ($0.24\%$) lack an end station identifier, while start station fields are missing just $0.03\%$ of the time.
This issue likely occurs when bikes are abandoned or returned outside a dock.
A complete per-column breakdown is available in the \href{https://github.com/davide-dona/nyc-bike-data-visualization/blob/main/src/notebooks/analysis.ipynb}{analysis notebook}.
Because valid origin and destination data is essential for spatial and distance metrics, these incomplete rows are dropped during preprocessing.

\paragraph{Trip Outliers}
Beyond missing values, a small number of trips are clear outliers.
In a representative month, about $315$ trips ($0.02\%$) last up to $25$ hours, appearing in the final bin of the duration histogram (Figure~\ref{fig:rides_duration}).
These likely reflect unreturned bikes rather than continuous rides, so trips exceeding a maximum-duration threshold are dropped. 
Additionally, around $27{,}000$ trips ($1.4\%$) start and end at the same station, resulting in a zero straight-line distance (Figure~\ref{fig:rides_distance}); because distance metrics are meaningless for these round trips, they are removed.
Finally, some trips report impossible distances over $11{,}000$~km, as an example, due to corrupted station coordinates, and are filtered out using a maximum-distance threshold.

\paragraph{Biases}
This dataset carries certain inherent limitations.
Because it relies exclusively on the Citi Bike system dataset, the findings may not accurately reflect the demographics of the entire population of cyclists in New York City.
Additionally, trip distances are calculated using the Haversine formula between the start and end stations; this straight-line metric serves only as a geometric approximation and cannot account for the actual routes or detours taken by riders.
Unfortunately, these structural data constraints cannot be resolved within the scope of our project.
